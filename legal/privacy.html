Privacy Policy — AliKa

Last updated: 06.10.2026
Publisher: ErenKa Software
Contact: alika.destek@gmail.com

1. Purpose of the application

AliKa is a transparent (non-hidden) parental control application designed to let a parent/guardian manage screen time on the device of a child in their care. The app does not run covertly: it is visibly present on the device, and lock screens and notifications are shown openly.

The app may only be installed by the device owner/guardian, with the child's knowledge. It may not be used secretly on another person's device without their consent, and such use is expressly prohibited.

Because it lets a parent see and limit how a child's device is used, the Android app is declared to Google Play as a parental-control monitoring tool (isMonitoringTool = child_monitoring). Its icon is never hidden, a persistent notification is shown while protection is running, and Google Play Protect may tell the device user that a monitoring app is installed.

Android accessibility service (Settings Guard)

Settings Guard is optional and off by default. Before Android's accessibility settings are opened, AliKa shows a separate in-app disclosure with Accept and Decline buttons; declining does not limit any other feature.

  • What it reads: only events from Android's Settings and app-manager / package-installer screens. On those screens it reads the app/package name, visible text and content descriptions. It receives nothing from messaging apps, browsers or any other app.
  • Why: to ask for the parent PIN when someone tries to uninstall or force-stop AliKa or turn off its device-administrator protection.
  • What is kept: screen text is not stored or shared. When a screen is blocked, only the system package name of that event is written to the local event log on the device. Nothing from this service is sent to ErenKa Software or any third party.
  • How to stop it: turn AliKa off in Android's accessibility settings at any time.

3. Storage and sharing of data

  • Parental-control content stays on the family's devices. Machine-wide Windows settings and reports are stored under %ProgramData%\AliKa\; the current Windows user's learning library and local state are stored under %LocalAppData%\AliKa\. Android usage history, child profiles, messages, learning content, rules and visited-domain history remain on the device or move directly between paired family devices on the approved local network.
  • AliKa sends only the limited Android family-subscription metadata described below to an AliKa-operated licensing service. It does not send child content, usage history, messages, visited domains, location, Google account name or email, IMEI or Android ID to that service.
  • AliKa does not sell user data or share it with advertising or analytics providers.
  • The app contains no advertising networks or third-party analytics SDKs.
  • The PIN is not stored in plain text; it is hashed with PBKDF2-HMAC-SHA256.

Optional local family network

If the parent explicitly enables Family Network features and pairs family devices, supported data is transferred directly between the paired devices on the approved local network using encrypted communication. This optional transfer does not pass through an AliKa-operated cloud service. The feature can be turned off by the parent.

Android family subscription verification

To let one Google Play family subscription work on up to 10 paired Android phones, tablets and TVs, AliKa uses a limited licensing service. It processes a random AliKa family identifier, a random AliKa device identifier, a SHA-256 digest of the device public key, the device role, revocation status, and the Google Play product, subscription status and paid-period end time. Purchase and refresh tokens are retained only as SHA-256 digests; their plain values are not stored. Google account names and email addresses are not collected by the licensing service.

This metadata is used only for app functionality, subscription verification, fraud prevention and enforcement of the 10-device limit. Transfers use HTTPS/TLS. Inactive or expired family-license records and their device records are permanently deleted within 90 days. Google Play separately processes purchases under Google's own privacy terms.

Android web filter (local VPN)

On Android the web filter uses a local VPN (VpnService) on the device. It only inspects DNS requests (the domain names of visited sites) to block listed sites and non-safe-search content. No encrypted tunnel is created and no traffic is routed to an AliKa server; only ordinary DNS resolution goes to a public resolver. Page content is not read. Visited domain names remain on the device. The parent must enable the filter after an in-app prominent disclosure and explicit consent, and can turn it off at any time.

(If cloud sync is added in the future, this section will be updated and separate, explicit consent will be requested.)

Optional website AI assistant

The AI assistant on alika.tr is separate from the AliKa applications and is off until the visitor opens it and accepts the disclosure. When the visitor sends a message, the following limited information is sent to the AliKa assistant service on Google Cloud and processed by Google Gemini solely to produce the requested answer:

  • the message, up to six recent messages in the same browser session, the selected site language, and the current page path;
  • ordinary technical request metadata handled by the hosting platform, such as IP address and user-agent. A one-way, short-lived in-memory hash is used for basic abuse rate limiting.

ErenKa Software does not persist assistant conversation content, does not use it for advertising, and does not connect it to AliKa application data. The browser keeps only the session-level disclosure choice and recent conversation needed to continue that open chat. Closing the browser session clears that client-side state. Visitors must not enter a child's name, PIN, password, school, health information, browsing history, or other personal data. The assistant can be avoided entirely by leaving it closed and the same public product pages remain available without it.

4. Children's privacy (COPPA / GDPR-K)

This app processes data on behalf of a legal guardian, for the sole purpose of managing their own child's device. Data is not used for marketing, profiling, or third-party sharing. The guardian can delete history and library items through the parent panel; the steps for deleting all local data are stated below.

5. User rights

  • Access: The parent panel displays locally collected parental-control data. The Android subscription screen shows the family and device identifiers needed to identify licensing metadata.
  • Deletion: The parent panel can delete history records and imported library content. Uninstalling the Microsoft Store/MSIX package removes the package, service, and running processes, but deliberately retains %ProgramData%\AliKa\ and %LocalAppData%\AliKa\ so a reinstall can resume without data loss. To erase everything, delete the first directory as an administrator and the second as the relevant Windows user after uninstall. The classic Setup uninstaller separately offers to delete %ProgramData%\AliKa\; silent update/uninstall retains data.
  • Android local-data deletion: The parent can clear history, family chat and imported learning content from the parent panel. Removing AliKa from an Android device removes that app's local data from the device.
  • Android licensing-metadata deletion request: Email alika.destek@gmail.com with the subject “AliKa Android data deletion request” and include the AliKa Family ID and Device ID shown on the app's subscription screen. Do not send a child's name, PIN, messages, browsing history or purchase token. ErenKa Software may ask for a device-bound verification response before deletion so another person cannot delete a family's record. After verification, the random family/device identifiers, public-key digest, device role, revocation state, token digests and retained subscription-status metadata are permanently deleted. Records for an inactive or expired family are also deleted automatically within 90 days. Data that Google retains for Play purchases is controlled by Google and is not deleted by AliKa.
  • Consent: An explicit consent screen is shown at first setup; functions do not start until it is accepted.

6. Security

Local settings are protected by a parent PIN. Android licensing-service transfers use HTTPS/TLS, device public keys and hashed tokens; access to production records is limited to the service identities required for verification and retention cleanup. Device security (disk encryption and operating-system updates) remains the user's responsibility.
